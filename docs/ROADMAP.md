# Roadmap

## Vision

**Who it is for:** designers and production managers at sign-making shops.

**Problem:** standardized signage (door plates, wayfinding signs, nameplates) requires a lot of repetitive manual
work in CorelDRAW — opening templates, filling in text, exporting print and laser files. It is slow, error-prone
and hard to scale.

**In one sentence:** let an AI agent operate CorelDRAW like a senior designer and batch-generate production-ready
signage files from Excel data.

### Success criteria

- A designer prepares a template and an Excel sheet once; every sign is then generated by the agent with no manual work.
- A single door plate drops from 5–10 minutes (manual) to under 30 seconds; a batch of 500 signs takes under 30 minutes.
- Exported print PDFs and laser DXFs are used directly on shop equipment without further adjustment.
- People only do final spot checks instead of operating CorelDRAW record by record.

### Out of scope

- Original creative design (the agent has no spatial/aesthetic judgement and does not replace designers).
- Complex free-form curve drawing (product shapes, logo creation).
- Aesthetic color judgement (only CMYK/RGB checks, not "does it look good").
- Native editing of non-CorelDRAW formats (AI/PSD/Sketch internals).
- Real-time collaborative editing.

### Users

| User | Core need | Typical scenario |
|---|---|---|
| Sign-shop designer | Less repetitive work, batch generation | An office building orders 500 door plates; hand the customer's Excel data and a CDR template to the system and generate all files |
| Production manager | Output meets production standards | Check that generated files have bleed, CMYK and crop marks, and that DXF layers match the laser cutter's requirements |
| Account manager | Fast turnaround on client revisions | The client changes a font/color/logo — edit the template or Excel and rerun |

## Status

**Done**

- MCP server framework: CorelDRAW COM connection management and unified error handling
- Core tools: document management, text replacement, PDF/DXF export, template open + replace
- End-to-end single-record door plate generation (open template → replace text → preflight → export PDF/DXF)
- Visual preview feedback (`export_preview_png` → agent visual check → iterate)
- MCP server HTTP mode (`streamable-http`, configurable via env, `.mcp.json` for local Claude/OpenCode)
- Streamlit chat UI (`run_single_stream` generator)
- Batch merge fixes: `merge_record` / `batch_merge` registered; documents are closed after batch runs
- Code quality fixes: ICC profile loading in `export_pdf`, `check_missing_fonts` detection
- Template management: `list_templates`, apartment door plate (S05303) config, size variants (character count → width)
- Engineering drawings: `populate_title_block` (project name / order no. / part no. / designer) + CDR frame template

**Deferred (infrastructure)**

- LiteLLM proxy on a company server — central API key management, usage monitoring, multi-model routing
- Migrate the agent orchestration layer (`runner.py`) to LangGraph, with RAG and persistent memory (depends on the proxy)

**Designed, not started ("company dispatch" mode)**

- Task queue — central SQLite queue with task creation, status tracking and result storage
- Designer-side worker — `worker/polling_worker.py` polls the queue and executes tasks through the local MCP HTTP server
- Workstation registry — registration, heartbeat, dispatching tasks to online workstations
- Concurrency lock — local file lock so a worker and the local agent never drive CorelDRAW at the same time

## Backlog

**Features**

- Multiple CorelDRAW instances in parallel (several VMs processing different batches of a large order)
- Web UI / order system integration — submit jobs via API, show progress and results on a web page
- Automatic quoting based on size, material and process, linked to the generation flow
- Operation log and traceability — record parameters, time and result of every generation for audit
- COM crash reconnection improvements
- Task queue management
- Multi-template management and versioning

**Technical debt**

- Batch mode in `runner.py` should iterate over records in code instead of relying on the LLM to loop
- Agent session persistence — resume an interrupted job without losing context
- Token usage and cost tracking
- Check for 64-bit Python at startup (32-bit Python makes COM calls fail silently)
- Inconsistent COM type numbers: text shape is 6 in `colors.py` but 3 (= curve) in `engineering.py`, `preflight.py`,
  `document.py`, `data_merge.py`; RGB checks use `color.Type == 1` (= Pantone, RGB is 5). Verify on the supported
  CorelDRAW versions and unify into one constants module
- Test coverage: `test_e2e.py` covers ~18 tool calls; 40+ MCP tools have no tests (all of shapes, data_merge,
  engineering, templates, colors, parts of export)

**CorelDRAW COM API capabilities not yet exposed as tools**

(Boolean operations, align/distribute, z-order, fit text to frame, add/delete/switch page and guidelines already
have tools.)

1. Advanced text layout (columns, tab stops, paragraph formatting, linked text frames)
2. Effects (Blend, Contour, Extrude, DropShadow, Lens, Envelope, Perspective, InnerShadow)
3. Page operations beyond add/delete/switch (move pages, page names, master page)
4. Color management (palettes, ColorManager, ICC profiles, color harmonies, convert to palette)
5. Document metadata (author, keywords, title, copyright, last author)
6. Print settings (PrintSettings, PrintJob, prepress, separations)
7. Grid and rulers
8. Symbols (Symbol, SymbolDefinition, SymbolLibrary, CreateSymbol, RevertToShapes)
9. Bitmap operations (resample, crop, convert to B/W, trace / PowerTRACE)
